## Feedback Type Control Refinement

On September 25, 2026, the feedback-type dropdown was replaced with a segmented-control-style native radio group showing **Support**, **Comment**, and **Suggestion** together. The existing `support`, `comment`, and `suggestion` submission values, default selection, draft recovery, and Worker contract remain unchanged.

The control uses `fieldset`, `legend`, radio inputs, and associated labels so it retains native single-selection semantics, arrow-key navigation, visible keyboard focus, and screen-reader names and state. Each segment uses the full 44-pixel control height, and all three segments remain in one horizontal row at supported viewport widths.

Frontend contract tests verify the three unchanged API values, the default and required selection, visible label associations, unchanged draft-value access, cache-safe stylesheet reference, focus styling, hidden native radio controls, equal-width horizontal columns, and exact 44-pixel height. The complete test suite passed 24 tests with zero failures, JavaScript syntax validation passed, and `git diff --check` passed. No Worker or Cloudflare configuration changed.

### Deployed Control Correction

Manual iPad inspection found that the first deployed version displayed native radio circles in a vertical fieldset instead of the intended segmented control. The corrected implementation uses a versioned stylesheet URL to avoid stale shared CSS, a dedicated visually-hidden radio class that remains in the accessibility tree, and an explicit full-width three-column grid. The control and every equal-width segment are exactly 44 CSS pixels tall, with 16-pixel centered labels, one rounded outer border, and two internal dividers. It remains horizontal at all supported viewport widths, including 320 CSS pixels; no responsive rule stacks the segments. Backend values and behavior remain unchanged.
